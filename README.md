# База исследования — тестовый MVP

Адаптивная форма для компьютера и смартфона. Данные сохраняются **на сервере в отдельную Excel-копию**, общую для клиентов одного сервера. Google Sheets не подключён. Использовать только вымышленные записи: в MVP нет авторизации, разграничения доступа и защиты для работы с реальными медицинскими данными.

## Разделы

1. Пациенты
2. Лабораторные результаты
3. Диагнозы — несколько строк, свободный код диагноза
4. ЭКГ
5. Скрининг
6. Второй этап — несколько строк
7. Рекомендации врача — общий текст и несколько кодированных рекомендаций

Названия полей и сопоставление столбцов взяты из приложенной книги. Исходный текст рекомендаций хранится на отдельном листе «Текст рекомендаций врача», как в книге. Код пациента вводится один раз и автоматически подставляется в связанные листы. Поля-формулы не показываются для ручного ввода.

Значения, уточнённые пользователем: СС риск — 1/2/3/4; группа здоровья — 1/2/3а/3б; BI-RADS — 1/2/3/4. Они действуют в форме и на сервере, списки проверки данных в исходном шаблоне сохранены. Пол — Мужской/Женский; курение — 0 (не курит сейчас), 1 (курит сейчас), 9 (неизвестно). Пустые значения сохраняются пустыми, не заменяются нулём. Остальные справочники импортированы из книги.

## Запуск

Требуется Python 3.10 или новее. Выполнять из каталога проекта:

```bash
python -m venv .venv
# Linux / macOS:
source .venv/bin/activate
# Windows PowerShell вместо предыдущей команды:
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Открыть http://localhost:8000 на компьютере. Для телефона в той же локальной сети открыть `http://IP_КОМПЬЮТЕРА:8000`; компьютеру может потребоваться разрешение входящих подключений в брандмауэре. У облачного сервера localhost относится к серверу: для открытия с другого устройства нужен предоставленный средой проброс порта либо отдельное размещение приложения с HTTPS. Публичная публикация в рамках этой версии не выполнялась.

Запускать **один процесс и одного worker**. Несколько клиентов этого процесса могут работать одновременно; запись сериализована блокировкой. Запись одной карты с двух устройств одновременно использует последнюю сохранённую версию. Не редактировать рабочую книгу в Excel одновременно с сервером: рабочая книга загружается при старте. Для внешних изменений остановить сервер, изменить книгу, затем запустить снова.

## Работа с файлами

- `data/01_База_исследования_рабочая.xlsx` — отдельная рабочая копия с исходным учебным примером и тестовыми записями MVP. Добавление/редактирование карты сохраняет книгу после нажатия «Сохранить в таблицу».
- Кнопка «Скачать Excel» возвращает текущую рабочую книгу со всеми листами и формулами.
- Исходный загруженный файл хранится за пределами проекта и не изменяется. Контрольная сумма записана в `docs/workbook-structure.json`.
- Можно выбрать другую **копию** шаблона переменной `RESEARCH_WORKBOOK`. Никогда не указывайте путь к оригиналу. Копия должна иметь ту же структуру.
- До 10 000 исходных строк на лист, как в шаблоне; сервер не расширяет диапазоны автоматически. Исходные расчётные листы рассчитаны на диапазоны самой книги, некоторые — на 100 пациентов.
- При редактировании заменяются только исходные записи выбранного кода в восьми используемых листах. Исходные записи других пациентов и остальные листы сохраняются. Для новой строки «Рекомендации врача» формула столбца D переносится из D2 шаблона, где она определена; пользователь этот столбец не редактирует. Для удаления строки диагноза/рекомендации удалить её в форме и сохранить карту.
- Сохранение выполняется через временный файл и атомарную замену рабочей копии. Произвольный текст записывается как текст, а не как Excel-формула.
- `openpyxl` сохраняет формулы, но **не вычисляет их**. Для пересчёта открыть скачанную копию в совместимом Microsoft Excel. Клинические алгоритмы и правила, отмеченные в книге как неутверждённые, приложение не реализует.
- Не удаляйте рабочую книгу. Делайте её резервную копию и скачивайте результат перед завершением облачной сессии: долговременное хранение вне этой среды пока не настроено.

## Проверка

Сервер должен быть запущен. Скрипт создаёт вымышленные карты `ТЕСТ_MVP_001` и `ТЕСТ_ФОРМА_<случайный код>`, проверяет создание, редактирование, валидацию, экспорт, даты и записи в листах, а также интерфейс 1440×1000 и 390×844. Запускайте его только на тестовой копии; при повторном запуске первая карта обновляется, для второй выбирается новый код. Для проверки сохранности оригинала и его формул скрипт ищет книгу в каталоге `attachments` этой среды; вне среды задайте путь к исходной книге в переменной `RESEARCH_SOURCE`. Если исходник недоступен, этот отдельный контроль пропускается и отмечается в отчёте.

```bash
python -m pip install -r requirements-dev.txt
python -m playwright install chromium
# Linux, если системный Chromium есть:
CHROMIUM_PATH=/usr/bin/chromium python tests/check_running_app.py
```

Можно задать `RESEARCH_URL` для другого адреса тестового сервера. Для установленного через Playwright браузера укажите путь к нему в `CHROMIUM_PATH`.

## Последующее подключение Google Sheets

Сейчас API-ключи и OAuth не нужны. Для будущей серверной записи понадобится:

1. Google-таблица с согласованной структурой, её ID и права на запись.
2. Проект Google Cloud с включённым Google Sheets API.
3. Один способ доступа: сервисный аккаунт с предоставленным ему доступом к таблице **или** OAuth-клиент с redirect URI и разрешением `spreadsheets` для выбранного аккаунта.
4. Хранение учётных данных в секретах сервера и согласование сопоставления листов, типов и формул при конвертации Excel.

Один API-ключ не даёт права редактировать закрытую таблицу. Секреты не нужно отправлять в чат. Подключение Drive в чате также не предоставляет автоматически полномочия самому веб-приложению.
