# Публикация на Render с HTTPS

Репозиторий: https://github.com/IamG69/- . Ветка: **main**.

Подготовлен Docker Web Service с одним процессом приложения и постоянным диском. Публикацию выполняет владелец аккаунта Render. Выбран Standard (2 GB RAM): книга содержит более 150 тысяч формул, и проверенный процесс использует около 500 MB уже при работе с несколькими тестовыми картами; тариф с 512 MB оставляет слишком мало памяти для сохранения Excel. Google Sheets, OAuth и API-ключи не требуются. Эта версия предназначена только для вымышленных тестовых записей; ссылка не ограничена авторизацией приложения.

## Что нажать

1. Откройте https://dashboard.render.com/ и зарегистрируйтесь или войдите. Можно выбрать **GitHub**.
2. Нажмите **New + → Blueprint**.
3. Подключите GitHub. Если приватный репозиторий не отображается, выберите **Configure account / Configure GitHub App**, разрешите Render доступ к репозиторию **IamG69/-**, затем вернитесь в Render. Подключение GitHub в Codex не заменяет это разрешение.
4. Выберите **IamG69/-** и нажмите **Connect**. Ветка — **main**, файл — **render.yaml** в корне репозитория.
5. Назовите Blueprint, например **Research MVP**, и просмотрите создаваемые ресурсы. В конфигурации: Web Service **research-mvp**, Docker, тариф **Standard (2 GB RAM)**, регион **Frankfurt**, один экземпляр и диск **research-workbook** размером **1 GB** в `/var/data`.
6. Проверьте стоимость в Render и добавьте платёжный способ, если Render его запросит. Постоянный диск требует платного сервиса; бесплатный диск не предусмотрен. Не заменяйте эту конфигурацию бесплатным сервисом без диска, если хотите сохранять введённые записи при перезапуске.
7. Нажмите **Deploy Blueprint / Apply** — название кнопки зависит от текущего интерфейса Render.
8. Откройте созданный сервис **research-mvp**. Дождитесь статуса **Live**. Во вкладке **Logs** должны появиться запуск Uvicorn на `0.0.0.0:10000` и успешные ответы проверки `/api/health`.
9. Вверху страницы сервиса нажмите выданный адрес вида **https://…onrender.com**. Это фактическая HTTPS-ссылка приложения; её выдаст Render после создания сервиса. Откройте тот же адрес в Safari на iPhone.
10. Нажмите **Новая запись**, задайте новый тестовый код, заполните поля и нажмите **Сохранить в таблицу**. Обновите страницу — запись должна остаться. Кнопка **Скачать Excel** скачивает рабочую книгу. Для проверки сохранности можно перезапустить сервис через Render и снова открыть карту.

После нажатия Deploy Render автоматически собирает Dockerfile; отдельные Build Command и Start Command для Docker задавать не нужно. Команда внутри образа — `python -m app.start`.

## Переменные и хранилище

`render.yaml` задаёт:

| Параметр | Значение |
| --- | --- |
| PORT | 10000 |
| RESEARCH_WORKBOOK | /var/data/research-working.xlsx |
| Health Check Path | /api/health |
| Persistent Disk Mount Path | /var/data |
| Instances | 1 |

Приложение слушает `0.0.0.0` и читает `PORT`; без переменной использует 8000. Uvicorn явно запускается с одним worker. Не добавляйте экземпляры или workers: файловое хранилище рассчитано на один процесс.

`templates/research-test.xlsx` — неизменяемый шаблон с вымышленными тестовыми записями. При первом старте он копируется на диск. При последующих стартах существующая книга сохраняется. Перезапуск и обычный redeploy с тем же диском не сбрасывают записи. Удаление сервиса/диска и создание другого сервиса не переносят данные автоматически. Перед такими действиями скачайте Excel.

При изменениях в структуре книги автоматической миграции нет. В этой публикации структура полей не менялась. Исходные формулы сохраняются, но пересчитываются в Microsoft Excel после скачивания; Python их не вычисляет.

## Если Blueprint не используется

**New + → Web Service → подключить репозиторий**. Выберите Docker, ветку main, Root Directory оставьте пустым, Dockerfile — `./Dockerfile`, тариф Standard (2 GB RAM), один instance. Укажите `/api/health` как health check. Добавьте переменные выше и постоянный диск `/var/data` размером 1 GB. Затем нажмите **Create Web Service**. Предпочтительнее Blueprint: конфигурация уже описана в репозитории.

## Если приложение не открылось

- **Build failed**: смотрите первый текст ошибки в Logs. Dockerfile должен находиться в корне выбранной ветки main.
- **Не обнаружен порт**: проверьте PORT и лог `Uvicorn running on http://0.0.0.0:10000`; не используйте жёстко заданный localhost в Start Command.
- **Permission denied / workbook not found**: проверьте диск `/var/data` и `RESEARCH_WORKBOOK=/var/data/research-working.xlsx`.
- **Записи пропадают после redeploy**: проверьте, что книга хранится на постоянном диске, а не внутри `/app/data`.
- **Изменили переменные**: сохраните их и дождитесь нового запуска сервиса.

HTTPS на домене Render предоставляется хостингом. Собственный домен для первого запуска не нужен. Никаких секретов из аккаунтов не нужно вставлять в код или отправлять в чат.
